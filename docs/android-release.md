# راهنمای ساده ساخت و نگه‌داری تکه‌چین

نام فارسی «تکه‌چین»، شناسه `ir.bbehrouz.tikechin` و آیکون قطب‌نما و جورچین با تأیید صریح مالک انتخاب شده‌اند. نام انگلیسی فنی Tikechin است. پشتیبانی: bh.behrouz73@gmail.com.

## نسخه نخست

نسخه نمایشی 1.0 و کد نسخه 1 حفظ شده‌اند؛ طبق مأموریت مالک، این اولین انتشار رسمی با شناسه نهایی است. نسخه قبلی با شناسه آزمایشی، برنامه‌ای جدا محسوب می‌شود. سابقه ثبت احتمالی در پنل فروشگاه از این محیط قابل مشاهده نیست؛ پیش از بارگذاری، نسخه‌های ثبت‌شده همان شناسه را کنترل کنید.

حداقل اندروید API 24، هدف و کامپایل API 36، JDK 21، Capacitor 8.6.2، Gradle 8.14.3 و AGP 8.13.0 هستند. Android Studio لازم نیست.

## ساخت با چند کلیک

1. تغییرات بازبینی‌شده را با اجازه مالک وارد main کنید.
2. مخزن https://github.com/b-behrouz/puzzle را باز کنید.
3. وارد Actions شوید و Android Release APK را انتخاب کنید.
4. Run workflow را بزنید و شاخه main را انتخاب کنید. اگر محیط بازبین دارد، اجرای همین نسخه را تأیید کنید.
5. منتظر نتیجه سبز موفق بمانید. در همان صفحه، از Artifacts بسته tikechin-release-apk را دانلود و ZIP را باز کنید.
6. فایل app-release.apk فایل نصب است. release-verification.txt گزارش امضا و مشخصات، و app-release.apk.sha256 هش فایل است. Artifact چهارده روز نگه‌داری می‌شود؛ نسخه لازم را در آرشیو خود نگه دارید.

گردش‌کار موجود از npm ci، npm test، ساخت منابع وب، Capacitor sync و فرمان ./gradlew --no-daemon assembleRelease استفاده می‌کند. فقط اجرای دستی روی main مجاز است. گردش‌کار Debug قبلی تغییری نکرده است.

## کلید اصلی را نگه دارید

کلید موجود از قبل ایجاد شده است. کلید جدید نسازید، آن را جایگزین نکنید و از کلید Debug برای انتشار استفاده نکنید. Alias برابر tikechin-release است. اثر انگشت عمومی SHA-256:

`e1fd70ec5faaecdec256676acbded1ac9617d4b102baceca60a507bd04e98a32`

کلید رمزدار و رمزهای آن را در محل خصوصی مالک و یک پشتیبان مستقل حفظ کنید. رمزها را جدا از فایل کلید، در مدیر رمز نگه دارید. فایل محلی DPAPI فقط در حساب ویندوز و رایانه مربوطه قابل بازخوانی است؛ به‌تنهایی پشتیبان قابل بازیابی روی رایانه جدید نیست. Secrets گیت‌هاب جایگزین پشتیبان مالک نیست.

چهار Secret موجود در Environment به نام android-release هستند: ANDROID_KEYSTORE_BASE64، ANDROID_KEYSTORE_PASSWORD، ANDROID_KEY_ALIAS و ANDROID_KEY_PASSWORD. متغیر عمومی ANDROID_SIGNING_CERT_SHA256 اثر انگشت بالا را نگه می‌دارد. قانون Environment فقط Branch main است. فایل کلید موقت پس از ساخت پاک می‌شود و در Artifact قرار نمی‌گیرد. Base64 رمزگذاری امنیتی نیست و مانند خود کلید محرمانه است.

Gradle اطلاعات امضا را فقط از محیط پردازش می‌گیرد: ANDROID_KEYSTORE_PATH، ANDROID_KEYSTORE_PASSWORD، ANDROID_KEY_ALIAS و ANDROID_KEY_PASSWORD. نبود هر مورد، وظایف Release را متوقف می‌کند. نیازی به تغییر Secrets برای نام یا شناسه جدید نیست؛ همان کلید استفاده می‌شود.

## بررسی فایل دریافت‌شده

گزارش موفق باید شناسه ir.bbehrouz.tikechin، نام تکه‌چین، نسخه 1.0، کد 1 و اثر انگشت اصلی را نشان دهد. ابزار apksigner در خود GitHub Actions امضا را بررسی می‌کند و اسکریپت، نام و شناسه را با Capacitor و نسخه را با Gradle تطبیق می‌دهد. منابع بازی بایت‌به‌بایت با ورودی وب مقایسه و نبود فایل‌های رایج کلید و تنظیمات امضا در APK بررسی می‌شود.

برای بررسی مستقل با Android SDK Build Tools:

`apksigner verify --verbose --print-certs app-release.apk`

در PowerShell، فرمان `Get-FileHash .\app-release.apk -Algorithm SHA256` باید همان هش موجود در فایل همراه را برگرداند. فقط گواهی عمومی و هش‌ها قابل اشتراک‌اند؛ رمز و فایل JKS را در چت، مخزن، issue یا لاگ قرار ندهید.

## نسخه‌های بعدی

در android/app/build.gradle، versionCode را برای نسخه بعدی از 1 به 2 و versionName را مثلاً از 1.0 به 1.0.1 تغییر دهید. هر انتشار بعدی با همان شناسه و همان گواهی، کد نسخه بزرگ‌تری لازم دارد. نسخه npm در package.json نسخه داخلی ابزار وب است و نسخه APK را تعیین نمی‌کند. تغییرات را در شاخه مستقل و PR بازبینی و سپس همان گردش‌کار را اجرا کنید.

نصب آزمایشی قبلی با شناسه متفاوت، فضای ذخیره جدا دارد. پیشرفت آن خودکار به برنامه جدید منتقل نمی‌شود. الگوریتم ذخیره و کلیدهای localStorage بازی تغییر نکرده‌اند. پس از انتشار شناسه را ثابت نگه دارید. نسخه Debug با گواهی دیگر را نیز با نسخه Release قابل به‌روزرسانی فرض نکنید.

## آماده‌سازی پنل بازار

متن قابل کپی در docs/bazaar/listing-fa.txt، سیاست حریم خصوصی در docs/bazaar/privacy-fa.md و وضعیت بررسی‌ها در docs/bazaar/readiness-fa.md هستند. با حساب توسعه‌دهنده خود، شرایط جاری پنل را بخوانید؛ سپس برنامه را با نام و شناسه تأییدشده ایجاد، APK و اطلاعات محصول را طبق همان فرم وارد و تصاویر واقعی نسخه اندروید را انتخاب کنید. اطلاعات سنی، تبلیغات و پرداخت را مطابق همین نسخه پاسخ دهید: تبلیغ و پرداخت درون‌برنامه‌ای پیاده نشده‌اند. نسخه‌های آینده با این امکانات به بررسی دوباره SDKها و حریم خصوصی نیاز دارند.

هیچ ارسال یا انتشار نهایی بدون تأیید مالک انجام نمی‌شود. در این مأموریت فایل‌ها و متن‌ها آماده می‌شوند. محدودیت‌های دقیق تصویر، قالب‌های مجاز پنل و سیاست‌های جاری بازار باید در منبع رسمی و پنل کنترل شوند؛ متن کامل منابع رسمی از ابزار فعلی قابل دریافت نبود.
